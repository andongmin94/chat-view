- [x] **G1-01 — 투명 개인 HUD와 자체 텍스트 채팅 화면.** 실제 치지직 채널 확인은 G4-06이다.
- [x] **G1-02 — 클릭 통과, 이동·크기 조절, 위치·DPI 저장, 단축키.** 기존 네이티브 구현과 Windows 검사가 있다.
- [ ] **G1-03 — 실제 게임에서 가독성과 조작감 완성.** [실환경 미확인] 포커스/입력 방해를 확인하고 개선한다.

## G2. OBS 플러그인으로 연동하고 개인 HUD만 송출에서 제외한다

완료 기준: **스트리머에게 HUD가 계속 보이고 시청자 영상에는 없다.** HUD 숨김을 성공으로 처리하지 않는다. 공개 광고는 G5의 별도 출력이다.

- [x] **G2-01 — OBS 플러그인, 설정 진입, HUD 실행·종료 연동.** OBS/HUD 프로세스 분리와 기존 제어 경로가 있다.
- [ ] **G2-02 — 원컴에서 가독 HUD와 송출 제외 동시 달성.** [부분 구현] 위험 시 숨기는 보호 정책을 실제 지원 영상 경로로 해결한다.
- [ ] **G2-03 — 방송 시작·장면 전환·복귀와 지원 조건 안내.** [부분 구현·실환경 미확인] `READY TO STREAM`을 방송 전체 보장으로 사용하지 않는다.

## G3. 게임 PC에 OBS 없는 투컴 방송에서 사용한다

완료 기준: 게임 PC에는 게임과 챗뷰만, 송출 PC에는 OBS/플러그인이 있다. 개인 HUD는 계속 보이며 송출 영상에는 섞이지 않는다.

- [x] **G3-01 — 동일 HUD의 OBS 비종속 개발 실행.** 명시적 `--companion`, 로그인/연결창, 중복 실행 방지·종료와 부모 OBS 없는 routine 실행 검사가 있다.
- [ ] **G3-02 — 두 PC를 같은 사용자의 채팅·방송 세션에 연결.** [부분 구현] 브라우저 동의에 게임/송출 역할을 결합하고 동일 계정의 논리 세션, 단일 송출 역할, 저장·갱신·개별 철회를 구현했다. 서버 재시작 후 기존 PC 승인과 역할을 유지해 복원한다. 네이티브 실행 역할 자동 연동·역할 상태 UI·OBS 출력/방송 생명주기 전달은 남았다. 캡처 상태는 `unverified`이며 하드웨어 ID나 별도 기기등록은 없다.
- [ ] **G3-03 — OBS 없이 개인 HUD가 빠진 영상 전달 경로.** [미구현·방식 미확정] 캡처카드/출력 구성을 선정·구현한다. OBS 숨김 실행·프로젝터·다른 방송 프로그램 필수 설치로 우회하지 않는다.
- [ ] **G3-04 — 투컴 설치·실사용 연결과 실제 영상 확인.** [하드웨어 필요] 채팅·재연결·종료·지연/자원 사용과 HUD 없는 녹화를 함께 확인한다.

## G4. 치지직부터 자체 채팅 플랫폼을 만든다

완료 기준: 개발자 비밀키나 수동 표시키가 아니라 로그인·동의로 자기 채팅을 보고, 방송 중 유지하며 재실행 후 이어 쓰고 로그아웃할 수 있다.

- [x] **G4-01 — 공식 인증·채널 조회·채팅 구독 모듈.** 합성 제공자/실제 Socket.IO 라이브러리 검사와 실계정 확인을 구분한다.
- [x] **G4-02 — 서버에서 자체 네이티브 화면까지 메시지 전달.** HTTP/WebSocket → WinHTTP → HUD/WebView2를 합성 메시지로 확인했다. D1은 남아 있다.
- [x] **G4-03 — 로그인 버튼 → 시스템 브라우저 동의 → 앱 복귀 → 채팅 표시.** 요청별 verifier/challenge와 소유자/승인세대 결합이 있다. 수동 표시키 복사는 정상 UX에서 제거했다. 실계정 확인은 G4-06이다.
- [x] **G4-04 — 실행 중 자동 갱신, 선택적 연결 유지, 재연결, 로그아웃.** `chat:renew`는 실행 중 갱신, ‘이 PC에서 연결 유지’는 Windows DPAPI 재실행 저장을 결정한다. native 승인 자격증명은 서버에 해시로만 저장한다. provider 저장은 별도 G4-05 책임이다.
- [ ] **G4-05 — 여러 스트리머가 사용하는 운영 서비스.** [부분 구현] 직접 TLS, 서버 `/users/me` 기반 계정 격리, 단일 upstream, 브라우저 인증/CSRF, 갱신/철회에 이어 **AES-256-GCM 승인 저장·외부 키파일 검증·원래 만료시각을 유지한 재시작 복원**을 구현했다. 갱신 전 durable claim과 성공 결과의 revision 검사로 중단/늦은 응답 재사용을 막고, 제공자 철회와 PC 승인을 원자적으로 제거한다. 유효 승인 아래의 일시적 채팅 장애는 승인 삭제와 분리했다. 운영 접근/용량 제한·실제 인증서/호스팅·키/백업 운영·Windows 실제 서비스 연결은 남았다. 단일 인스턴스용이며 loopback probe를 공개 서버로 바꾸지 않았다.
- [ ] **G4-06 — 실제 치지직 계정 전체 확인.** [비공개 앱/채널 승인 필요] 실제 동의·메시지·장시간 유지·재연결·로그아웃/권한 철회를 확인한다.

## G5. 광고 선택 → 시청 실적 → HP → 광고 수익

완료 기준: 선택 광고가 시청자에게 노출되고 허용된 시청시간 관련 근거로 HP/수익 기록이 변한다. 개인 HUD와 시험 수치는 지급 가능한 실적이 아니다.

- [ ] **G5-01 — 배너/캠페인 목록·선택·중지.** [미구현] 한 광고의 끝까지 동작하는 흐름부터 만든다.
- [ ] **G5-02 — 선택 광고의 별도 OBS 공개 출력.** [미구현] 확인한 위치/크기, 변경/중지, 개인 HUD 분리가 필요하다.
- [ ] **G5-03 — 시청시간 관련 실적 집계.** [미구현·권한/계측 필요] 방송 시간·추정 시청자 시간·실측 시청시간을 구분하고 누락/중복/중단을 처리한다.
- [ ] **G5-04 — 서버 계산 HP·수익 내역.** [미구현·규격 미정] 비지급 시험 흐름과 예상/확정 구분부터 만든다. HP 0에서만 지급 조건을 임의로 만들지 않는다.
- [ ] **G5-05 — 실제 유료 운영·정산.** [미구현·운영 규칙 필요] 단가·예산·배분·지급, 중복/초과 방지, 부정 실적 검토, 개인정보·광고 고지·지급 기록이 필요하다.

## 현재 근거와 세션 인수인계

- **이번 코드:** 이 문서와 같은 커밋의 `provider-grants.mts`, `creators.mts`, `session-store.mts`, `server/main.mts`, 계정 안내·키파일 설정, 저장/재시작/실제 gateway 회귀 검사다. 기존 서비스 테스트 fixture를 공유해 기존 9개 회귀를 유지했다. 네이티브 소스·의존성 버전·lockfile·CI 기준은 바꾸지 않았다.
- **이번 직접 실행:** Linux Node **22.16.0**, `node --experimental-strip-types --test tests/provider-grants.test.mts tests/platform-service.test.mts tests/provider-restart.test.mts` **28/28 통과, 실패/skip 0**. 실제 HTTP/SQLite reopen, 기존 두 PC 승인 복원, 단일 갱신, 철회, 오류 격리와 갱신 claim 뒤 child-process 비정상 종료를 검사했다. provider/chat/gateway는 합성 경계다.
- **이번 타입/검증 범위:** 저장소·키파일 모듈/테스트의 strict type 검사는 환경의 TS **5.8.3** / @types-node **25.1.0**으로 통과했다. 변경 .mts 구문 검사를 실행했다. 로컬 DNS/패키지 접근 문제로 locked `npm ci`, 전체 test/typecheck/audit와 `provider-restart-wire.test.mts`의 실제 ws 실행은 로컬에서 하지 못했다. 해당 wire 검사는 기존 원격 contract CI 대상이며 **이번 커밋의 원격 성공은 아직 확인하지 않았다**. 실제 인증서·CHZZK 계정·Windows 재시작·투컴 하드웨어·qualification은 수행하지 않았다.
- **확인한 직전 원격 기준:** `c081bb67dbfa1a6baafc649d8ff74092109af2ee`의 CHZZK **#30 / 35548221833**에서 Windows/Linux × Node22/24 locked install, audit, 전체 테스트, strict type, manifest 확인 모두 성공. Windows **#322 / 35548221963** routine 빌드/테스트도 성공. qualification 단계는 건너뛴 것이며 이번 변경 검증으로 대체하지 않는다.
- **운영 제한:** 정상 재시작은 같은 키/DB와 유효 PC 승인으로 복원한다. 갱신 도중 중단·모호한 응답은 재동의가 필요하다. 키 자동 재생성, 과거 DB로의 안전한 rollback, 다중 인스턴스, 실계정/영상 보장은 제공하지 않는다. 키와 백업은 별도 보호 관리한다.
- **ZIP 의존 없음:** 코드·테스트·설정·현재 지시는 OBS 이력만으로 이어간다. 옛 로그인/device-enrollment/remembered-connection ZIP은 재개 자산이 아니다.
