### 구현

- 게임/송출 연결창에서 로그인 대기 중 **연결 중지**를 선택하면 로컬 채팅·승인 페이지 재열기를 즉시 차단하고 기존 WinHTTP 작업자가 원래 `/display/login/<id>/cancel`로 요청한다. 브라우저 주소의 ID만으로는 취소할 수 없으며 원래 앱의 verifier가 Authorization 헤더로 필요하다. 별도 권한·DB·역할 변경·게임 영상 출력·광고 재선택은 없다.
- 서버 `BrowserLogin.cancel`은 요청의 원래 만료 시각까지 검증값에 결합된 취소 상태를 유지한다. 취소 후 브라우저 GET·승인/거부·앱 poll 모두 종료되고, 이 응답만 재확인할 수 있다. 취소가 선행하면 승인/수집을 막고, 이미 앱이 수집한 역할·채팅/광고·다른 계정/PC는 철회하지 않는다. 없는 요청, 인증 실패, 만료, 수집 완료는 취소 성공으로 보이지 않는다.
- 취소 네트워크는 UI/OBS callback 밖에서 별도 취소 가능한 짧은 작업으로 처리한다. 서버의 `cancelled:true` 응답을 직접 확인한 경우에만 **서버 취소 확인**으로 표시한다. HTTP 응답 유실, 이미 수집됨, 시작 응답이 없어서 id 불명, 기한 초과 및 종료 경합은 **서버 취소 미확인**이다. 앱 종료는 확인을 주장하지 않는다.
- 확인 완료 전에는 중복 새 로그인을 시작하지 않으며, 확인/미확인 모두 사용자가 기존 `로그인 / 연결`을 다시 선택한다. 이전 브라우저에 남은 요청은 자체 상태만 안내하며 새로운 역할이나 승인으로 자동 전환되지 않는다. 로그인 재열기, 외부 페이지 전환, HUD 보호와 WGC/광고 분리는 유지했다.
- 서버 취소·인증·만료·수집 경합/다른 승인 보존 검사를 새 Node/실제 HTTP·SQLite 회귀 검사에 추가했다. 기존 Windows 네이티브의 합성 WinHTTP·실제 WebView2 흐름에서 한 번의 서버 취소 확인과 **서버는 취소됐어도 HTTP 응답을 유실한 상황**을 구분해 확인한다. 새 Node dependencies·DB schema·CI/CTest 한도는 변경하지 않았다.

## 다음 사용자 흐름

이번 서버-앱 취소 흐름의 실제 CI 결과를 먼저 확인한다. 다음은 **취소가 미확인인 경우 브라우저의 오래된 요청을 실제로 확인 → 현재 앱의 새 로그인 확인 번호와 구분 → 새 승인을 직접 완료**하는 사용자 흐름이다. 응답 유실을 철회 완료로 주장하지 않고 다른 연결·영상·광고는 유지한다.

물리 수신 HUD 제외 전 G3 완료 금지. 실계정·장시간/배포·유료 노출·HP/보상 규격·인프라는 미완료다. 비밀은 대화/공개 저장소에 넣지 않는다. main·새 장기 브랜치·검증 태그·강제 push·옛 ZIP·게임 PC OBS·자동 장면 변경·렌더 ACK 수익 환산은 사용하지 않는다.
