# ChatView 작업 목표 체크리스트

갱신: 2026-09-28 (Asia/Seoul). 현재 구현 기준: `8fa41db5baf8b1988dd799fb2920a808e2fe3517` — **D5 실행 한정 승인 로그아웃 수정 및 routine 검증 완료**. 이번 결과 기록은 코드 변경 없는 문서 보완이다.
이 파일이 유일한 현재 작업 목록이다. 목표는 [PRODUCT.md](../PRODUCT.md), 구현·검증 운영은 [development-workflow.md](development-workflow.md), 책임 구분은 [architecture.md](architecture.md)를 따른다.

> 최종 제품: 한 화면에서 채팅을 읽고 개인 HUD는 시청자에게 노출하지 않으며, 게임 PC에 OBS가 없는 투컴을 지원하는 챗뷰 자체 플랫폼. 스트리머가 선택한 공개 광고의 시청시간 기반 실적을 HP 진행과 광고 수익으로 연결한다.

## 체크 규칙과 현재 위치

`[x]`는 **해당 항목의 좁은 개발 구현 범위**가 OBS에 반영되고 관련 근거가 있다는 뜻이다. 전체 제품·실계정·실제 방송·배포 완료가 아니다. 체크 개수로 완성도 퍼센트를 계산하지 않는다.

기존 HUD·OBS·companion·자체 채팅·브라우저 로그인·갱신·선택적 연결 유지·다중 계정·암호화 승인 복원·실행 역할 동의·공유 세션 표시 위에 **저장 여부와 관계없이 현재 승인으로 서버까지 로그아웃하는 경로**를 구현하고 실제 네이티브/서비스 회귀로 확인했다. D5는 이 좁은 범위에서 종료했다. G4-05/G3-02 전체는 부분 구현이다.

**다음 사용자 흐름: 승인된 송출 역할의 OBS 출력 시작/중지와 같은 세션의 상태 갱신.** 이번 변경은 이 흐름에 앞선 로그아웃/역할 반환까지이며, 실제 OBS 출력 보고는 아직 추가하지 않았다. 열린 표시 소켓을 OBS 실행 증명·영상 제외·광고 실적으로 사용하지 않는다. G3-03과 G5를 삭제하거나 무기한 연기하지 않는다.

## G1. 한 스크린에서 게임·작업과 채팅을 함께 본다

완료 기준: 실제 지원 게임/창 모드에서 채팅이 읽히고 게임 조작을 방해하지 않는다. main의 핵심 UX를 계승하되 Electron 코드를 유지할 의무는 없다.

- [x] **G1-01 — 투명 개인 HUD와 자체 텍스트 채팅 화면.** 실제 치지직 채널 확인은 G4-06이다.
- [x] **G1-02 — 클릭 통과, 이동·크기 조절, 위치·DPI 저장, 단축키.** 기존 네이티브 구현과 Windows 검사가 있다.
- [ ] **G1-03 — 실제 게임에서 가독성과 조작감 완성.** [실환경 미확인] 포커스/입력 방해를 확인하고 개선한다.

## G2. OBS 플러그인으로 연동하고 개인 HUD만 송출에서 제외한다

완료 기준: **스트리머에게 HUD가 계속 보이고 시청자 영상에는 없다.** HUD 숨김을 성공으로 처리하지 않는다. 공개 광고는 G5의 별도 출력이다.

- [x] **G2-01 — OBS 플러그인, 설정 진입, HUD 실행·종료 연동.** OBS/HUD 프로세스 분리와 기존 제어 경로가 있다.
- [ ] **G2-02 — 원컴에서 가독 HUD와 송출 제외 동시 달성.** [부분 구현] 위험 시 숨기는 보호 정책을 실제 지원 영상 경로로 해결한다.
- [ ] **G2-03 — 방송 시작·장면 전환·복귀와 지원 조건 안내.** [부분 구현·실환경 미확인] `READY TO STREAM`을 방송 전체 보장으로 사용하지 않는다.

## G3. 게임 PC에 OBS 없는 투컴 방송에서 사용한다

완료 기준: 게임 PC에는 게임과 챗뷰만, 송출 PC에는 OBS/플러그인이 있다. 개인 HUD는 계속 보이며 송출 영상에는 섞이지 않는다.

- [x] **G3-01 — 동일 HUD의 OBS 비종속 개발 실행.** 명시적 `--companion`, 로그인/연결창, 중복 실행 방지·종료와 부모 OBS 없는 routine 실행 검사가 있다.
- [ ] **G3-02 — 두 PC를 같은 사용자의 채팅·방송 세션에 연결.** [부분 구현] 동일 계정 논리 세션·단일 송출 역할·저장/갱신/철회·서버 재시작 복원, 실행 방식으로 고정된 `gaming`/`streaming` 동의와 공유 세션 표시가 있다. 현재 승인만 로그아웃해 송출 역할을 반환하고 다른 게임 연결/계정을 보존하는 경로까지 실제 native/service 회귀로 확인했다. 실제 OBS 출력 관측/방송 생명주기·하드웨어 확인은 남아 있고 `captureState`는 `unverified`다. 별도 기기등록/하드웨어 ID/수동 표시키는 없다.
- [ ] **G3-03 — OBS 없이 개인 HUD가 빠진 영상 전달 경로.** [미구현·방식 미확정] 캡처카드/출력 구성을 선정·구현한다. OBS 숨김 실행·프로젝터·다른 방송 프로그램 필수 설치로 우회하지 않는다.
- [ ] **G3-04 — 투컴 설치·실사용 연결과 실제 영상 확인.** [하드웨어 필요] 채팅·재연결·종료·지연/자원 사용과 HUD 없는 녹화를 함께 확인한다.

## G4. 치지직부터 자체 채팅 플랫폼을 만든다

완료 기준: 개발자 비밀키나 수동 표시키가 아니라 로그인·동의로 자기 채팅을 보고, 방송 중 유지하며 재실행 후 이어 쓰고 로그아웃할 수 있다.

- [x] **G4-01 — 공식 인증·채널 조회·채팅 구독 모듈.** 합성 제공자/실제 Socket.IO 라이브러리 검사와 실계정 확인을 구분한다.
- [x] **G4-02 — 서버에서 자체 네이티브 화면까지 메시지 전달.** HTTP/WebSocket → WinHTTP → HUD/WebView2를 합성 메시지로 확인했다. D1은 남아 있다.
- [x] **G4-03 — 로그인 버튼 → 시스템 브라우저 동의 → 앱 복귀 → 채팅 표시.** verifier/challenge와 소유자/승인세대 결합을 유지하며 실행 역할을 동의 전에 고정한다. 수동 표시키 복사는 정상 UX에서 제거했다. 실계정 확인은 G4-06이다.
- [x] **G4-04 — 실행 중 자동 갱신, 선택적 연결 유지, 재연결, 로그아웃.** 기존 갱신/DPAPI 연결 유지에 더해 `DisplayClient::sign_out()`이 메모리에 보관한 현재 승인을 수신 취소 후 동일 worker에서 해제한다. 저장된 현재 승인만 삭제하고 다른 저장 계정은 보존한다. 파일 삭제/서버 실패와 승인 결과 미수신은 완료로 표시하지 않으며 같은 실행에서 명시적으로 재시도할 수 있다. Windows #326의 실제 네이티브/서비스 로그아웃 검사로 D5를 종료했다. 일반 연결 중지/프로세스 종료나 승인 응답 유실까지 서버 철회 완료라고 보장하는 항목은 아니다.
- [ ] **G4-05 — 여러 스트리머가 사용하는 운영 서비스.** [부분 구현] 직접 TLS, `/users/me` 기반 격리, 단일 upstream, 브라우저 인증/CSRF, 갱신/철회, AES-256-GCM 승인 저장·키파일 검증·원래 만료시각을 유지한 재시작 복원이 있다. 갱신 전 durable claim/revision 검사와 원자적 철회가 있고 일시적 채팅 장애는 승인 삭제와 분리한다. 운영 접근/용량 제한·실제 인증서/호스팅·키/백업 운영·실계정은 남았다. 단일 인스턴스용이며 loopback probe를 공개 서버로 바꾸지 않았다.
- [ ] **G4-06 — 실제 치지직 계정 전체 확인.** [비공개 앱/채널 승인 필요] 실제 동의·메시지·장시간 유지·재연결·로그아웃/권한 철회를 확인한다.

## G5. 광고 선택 → 시청 실적 → HP → 광고 수익

완료 기준: 선택 광고가 시청자에게 노출되고 허용된 시청시간 관련 근거로 HP/수익 기록이 변한다. 개인 HUD와 시험 수치는 지급 가능한 실적이 아니다.

- [ ] **G5-01 — 배너/캠페인 목록·선택·중지.** [미구현] 한 광고의 끝까지 동작하는 흐름부터 만든다.
- [ ] **G5-02 — 선택 광고의 별도 OBS 공개 출력.** [미구현] 확인한 위치/크기, 변경/중지, 개인 HUD 분리가 필요하다.
- [ ] **G5-03 — 시청시간 관련 실적 집계.** [미구현·권한/계측 필요] 방송 시간·추정 시청자 시간·실측 시청시간을 구분하고 누락/중복/중단을 처리한다.
- [ ] **G5-04 — 서버 계산 HP·수익 내역.** [미구현·규격 미정] 비지급 시험 흐름과 예상/확정 구분부터 만든다. HP 0에서만 지급 조건을 임의로 만들지 않는다.
- [ ] **G5-05 — 실제 유료 운영·정산.** [미구현·운영 규칙 필요] 단가·예산·배분·지급, 중복/초과 방지, 부정 실적 검토, 개인정보·광고 고지·지급 기록이 필요하다.

## 현재 근거와 세션 인수인계

- **이번 코드:** `8fa41db5baf8b1988dd799fb2920a808e2fe3517`의 `display-client`, `native-chat-connection`, `saved-connection`, native logout CTest/fixture다. 저장 여부와 관계없이 실제 현재 승인을 사용한다. 수신 종료와 로그아웃 요청은 같은 mutex로 직렬화하며, 별도 취소 신호로 서버 해제를 종료 가능하게 유지한다. 파일은 같은 handle에서 승인 비교/삭제해 교체 파일을 잘못 지우지 않는다. 승인/메타데이터는 renderer나 OBS로 보내지 않는다.
- **Windows 실제 검사:** 같은 코드의 **#326 / 36432148164**, Windows x64 job **108960812242**에서 경고를 오류로 처리하는 빌드와 routine CTest **28/28 통과**. 로그에서 `chat-view-native-logout` 실행·성공(25.84초)을 직접 확인했다. 이 CTest는 아래 9개 시나리오를 순서대로 검사하고 하나라도 실패하면 실패 종료한다. 기존 display/session/companion 검사도 통과했다. qualification resource-soak는 제외했고 반복·설치·패키지 단계는 skip이며 통과로 세지 않는다.
- **새 로그아웃 회귀 9개:** 기억 안 함, 연결 유지, 중지 직후 로그아웃, 서버 503 후 명시적 재시도, 다른 저장 계정 보존, 미승인 요청 취소, 파일 삭제 실패/재시도, 저장된 승인만 있는 상태, 서버 해제 도중 종료. 실제 NativeChatConnection 버튼·WinHTTP·WebView2·DPAPI → 실제 서비스 HTTP/SQLite/gateway를 연결했다. provider/chat만 합성이다. 성공 경로의 서버 승인 제거·송출 역할 즉시 재승인·다른 계정/게임 승인 보존을 검증했다. 기존 테스트/제한은 삭제하거나 완화하지 않았다.
- **서버 계약 검사:** 같은 코드의 CHZZK **#34 / 36432148085**에서 Windows/Linux × Node22/24 네 조합의 locked install, audit, 전체 테스트, strict type, manifest 무변경 확인 모두 성공했다. native logout CTest 실행 근거는 이 Node 계약 검사가 아니라 위 Windows routine이다.
