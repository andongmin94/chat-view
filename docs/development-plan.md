### 구현

- `BrowserLogin.poll()`이 역할 교환 전에 요청을 지워 수집 충돌 때 원래 요청까지 소실하던 경로를 수정한다. 실제 SQLite가 송출 역할을409로 거부하면 먼저 성공한 연결을 보존하고 실패한 요청을 **재동의 대기**로 돌린다. 이전 access/generation을 폐기하며 원래 challenge·역할·remember·5분 만료·1초 조회 간격은 유지한다.
- 이후 앱 poll은 기존 `pending` 응답만 받고, 자리가 비어도 이전 동의로 자동 연결하지 않는다. 같은 채널에서 브라우저 동의를 다시 해야 새 역할을 수집한다. 다른 계정으로 이 실패 요청을 재승인할 수 없고, 정상 수집은 여전히 한 번만 허용한다. 철회/만료·용량429·저장 오류는 재동의 대기로 숨기지 않는다.
- 브라우저 동의 뒤에는 **아직 PC 연결 완료가 아님**과 기존 `/login/:id`의 상태 확인 링크를 표시한다. 해당 동의 계정만 수집 대기/재동의 안내를 읽는다. 수집 충돌은 기존 연결 확인·개별 해제·원래 요청 복귀 흐름으로 연결하며, 빈 자리에서는 다시 직접 동의할 form을 제공한다. GET은 승인·역할 이전을 하지 않는다.
- 게임 채팅·다른 계정·기존 공개 URL을 보존하고 새 승인/보고가 광고를 자동 선택하지 않는 흐름을 검사한다. 새 엔드포인트·의존성·DB 스키마·네이티브 프로토콜·HUD/WGC·공개 렌더러·회계·workflow·시간/픽셀 한도 변경은 없다. 네트워크에서 이미 성공한 응답 자체가 유실된 경우의 재전달을 구현한 것은 아니다.
