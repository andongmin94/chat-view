## 체크 규칙과 현재 위치

`[x]`는 명시한 좁은 개발 구현 범위의 반영과 검사 근거다. 전체 제품·실계정·실제 방송·배포 완료가 아니며 체크 개수로 완성도 퍼센트를 계산하지 않는다.

기존 companion의 선택 창 → 별도 SDR 출력에 **직접 잠금/전원/화면/장치 알림 → 검은 화면 중지 → 목록 무효화 → 수동 재선택**을 연결했다. 복귀만으로 영상을 다시 켜지 않는다. 같은 출력으로 재시작할 때 출력/덮개 HWND를 재사용하며, 다른 출력 선택이 기존 검은 창을 암묵적으로 파괴하지 못한다. **출력 창 닫기**는 먼저 검게 중지한 뒤 기본 '아니요' 확인을 거치며, 확인 중 상태가 바뀌면 해제를 취소한다. 최종 GPU 종료는 HWND를 유지한 채 동기 창 메시지만 처리한다.

이번 Windows 검사는 아직 성공으로 기록하지 않는다. 아래 검사 기록을 확인한 뒤 새 실패를 먼저 수정한다. **다음 사용자 흐름은 별도 출력의 식별용 시험 패턴 → 수신 화면에서 대상 확인 → 선택 게임 영상으로 전환**이다. 현재 출력 엔진/UI를 이어 쓰며 실제 캡처카드 녹화와 소프트웨어 시험을 구분한다. 기기등록·게임 PC OBS·다른 방송 프로그램·수동 표시키·HP/지급 규칙을 추가하지 않는다.

- [x] **G3-01 — 동일 HUD의 OBS 비종속 실행.** 명시적 companion·로그인·중복 방지·종료를 유지한다.
- [ ] **G3-02 — 같은 계정의 채팅·방송 세션 연결.** [부분 구현] 역할 동의·공유·저장 복원·로그아웃과 최근 송출/녹화 활성 상태 전달이 있다. 독립 보고 작업·단기 권한·만료/철회를 처리한다. 활동 기록은 선택한 시험 캠페인 한정이다. 장면/소스·다른 출력·실제 두 PC 확인은 남았다. 보고는 시청자 수신/캡처 제외 증명이 아니다.
- [ ] **G3-03 — OBS 없이 개인 HUD가 빠진 영상 전달.** [실험 구현·물리 검증 필요] WGC → D3D11/D2D와 직접 선택/확인/중지 UI를 유지한다. 복제·주 출력·HUD/게임/설정창 겹침·HDR·자체 창을 거절한다. 이번에 알림 기반 중단·선택 무효화, 실행 중 SDR 재검사, 출력창 재사용·명시적 해제, 메시지 처리형 GPU 종료를 보완했다. SDR·영상만·최대 4096이며 오디오/인코더/네트워크 영상은 없다. 실제 두 화면·캡처카드 녹화·게임·지연/자원·잠금/복귀/장치 상실은 미검증이다. 일반 출력창이므로 OS 오버레이·앱 종료 뒤 바탕화면까지 물리 차단하지 않는다. [기술 계약](window-video-output.md).
- [ ] **G3-04 — 투컴 설치·실사용·영상 확인.** [하드웨어 필요] 지연·자원·재연결과 HUD 없는 녹화를 함께 확인한다.

## 이번 근거와 한계

- **기준 확인:** 원격 OBS `e9983c3`에서 지정된 다섯 문서를 읽었다. 이전 `f544119`/Windows #337 `36537058084`의 33/33 성공은 그 커밋의 기존 기록이다. 이번 시작 조회에서 과거 job API가 404여서 새로 검증한 결과로 세지 않는다. #336의 테마색 덮개 실패와 #337의 수정 성공 상세는 `e9983c3` 이력에 남아 있다.
- **코드 검토에서 수정한 경로:** 기존 비디오 패널은 WTS를 직접 구독하지 않았고, 시작 시 기존 출력창을 파괴했으며, 출력 해제에 별도 확인이 없었다. GPU 작업이 HWND owner에 동기 메시지를 보낼 수 있는데 최종 종료는 UI에서 바로 join했다. 이번 수정/새 회귀가 해당 경로를 다룬다. 원래 코드에서 실제 OS 잠금·GPU 교착을 재현했다고 주장하지 않는다.
- **공식 계약 확인:** Microsoft WTS 등록/해제, DBT_DEVNODES_CHANGED, DXGI 다중 스레드/동기 메시지 지침과 PeekMessage의 sent-only 처리 계약을 확인했다. 구현은 기존 Windows API/STL만 사용하며 의존성 핀·서버/계정/광고·기존 시험 한도는 변경하지 않았다.
- **로컬 확인:** 변경 전 네이티브 네 파일의 Git blob 해시가 원격 원본과 일치하는 사본에서 수정했다. 로컬 GitHub DNS와 Windows SDK/실행 환경이 없어 전체 clone·Windows 빌드/실행은 하지 못했다. 텍스트 검토/바이트 대조를 실제 컴파일이나 테스트 성공으로 세지 않는다.
- **새 회귀:** `capture-worker-wait`는 동기 SendMessage를 처리하며 posted command/WM_QUIT를 보존하는 실제 스레드/창 검사다. `video-output-lifecycle`은 실제 HUD/패널/WGC/검정 덮개에 한 화면의 합성 출력 사각형과 시험 알림을 주입한다. 네 가지 중단 알림, 복귀 비재시작, 선택 무효화, HWND 재사용, 다른 출력의 암묵 해제 거절, 해제 취소/확인/확인 중 상태 변경, 설정창 닫기/열기, 활성 GPU 종료를 다룬다. 제품에는 topology 우회 설정이 없으며 두 화면·실제 잠금·hotplug 검사가 아니다.
- **이번 원격 검사:** 아직 미확인. 관련 Windows routine 결과를 확인해 이 항목을 갱신한다. 기존 WGC/companion/네이티브 채팅·로그아웃·출력 보고·배너 검사를 삭제하거나 제한을 늘리지 않았다. qualification/패키지 배포는 요청하지 않았다.
- **미검증:** 실제 확장 화면·캡처카드·수신 PC 녹화, 게임/보호 표면·다중 GPU·커서/OS 오버레이·실제 잠금/복귀/hotplug·장시간 자원/지연·오디오·실계정·호스팅·qualification. G3-03/G3-04와 D1–D4는 완료 처리하지 않는다. 종료/충돌 후 바탕화면 노출과 GPU/OS의 비실시간 종료 한계는 유지한다.
