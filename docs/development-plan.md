## 체크 규칙과 현재 위치

기존 로그인·갱신·암호화 승인 복원·역할 동의·현재 승인 로그아웃 위에 **송출·녹화 출력의 활성 상태 보고**를 연결했다. 기존 OBS frontend 관측과 로컬 IPC를 재사용하고 네이티브 독립 작업에서 보고한다. 승인된 송출 역할만 짧은 별도 보고 권한을 받는다. 같은 세션의 연결창은 최근 보고와 미확인을 구분하며 만료·철회·연결 종료에는 미확인으로 돌아간다. 개인 채팅 및 캡처 보호는 별도다. 이번 원격 결과는 아래에서 구분한다.

## 이번 근거와 한계

- **코드:** 기존 OBS frontend의 실제 streaming/recording 활성값 → 64바이트 IPC의 단일 원자적 관측값 → 기존 reader/네이티브 독립 WinHTTP 작업 → 기존 creator/gateway → 연결창이다. IPC 버전은 5이며 옛 ABI 우회는 없다. OBS callback에 네트워크를 넣지 않았다. 시각·상태만 전송하고 provider 비밀·장면·시청자·금융 데이터는 제외한다.
- **로컬 실행:** Linux Node 22.16.0에서 `tests/broadcast-output.test.mts` **5/5 통과**. 실제 SQLite/HTTP body 검사와 권한 분리·만료·순서·입력 제한이다. C++20 `tests/obs-output-test.cpp`를 `-Wall -Wextra -Werror`로 빌드해 **31 assertions 통과**했다. TS 5.8.3/@types-node 24.0.4로 관련 저장/출력 모듈과 이 테스트의 strict 검사를 통과했다. 변경 .mts 구문도 검사했다.
- **추가한 연결 검사:** 실제 서비스 HTTP/WebSocket의 계정별 보고, 열린 송출 연결 요구, 갱신/철회 후 늦은 body 거절, 읽기/갱신/보고 권한 분리, 순서/빈도·만료와 채팅 유지. Windows fixture는 실제 IPC reader/WinHTTP/연결창으로 송출·녹화 시작/중지, 보고 요청 지연 중 채팅 유지, 오래된 관측, 미확인 복귀·회복·로그아웃을 검사한다. OBS 관측 입력과 CHZZK provider/chat은 합성이며 실제 OBS 방송/영상 증거가 아니다.
- **이번 원격 검사:** 아직 미확인이다. 잠금 의존성 전체 검사와 Windows 실행은 로컬 DNS/SDK 제약으로 수행하지 못했으며 기존 원격 routine 대상으로 추가했다. 결과 확인 후 이 문서에 정확한 코드/run을 기록한다. 이전 성공으로 대신하지 않는다.

### 다음 세션 재개 지시

OBS 최신 ref에서 지정된 다섯 문서를 순서대로 읽고 이번 관련 검사를 확인한다. D5와 완료된 로그인/역할 작업을 재작성하지 않는다. 출력 관측 전달 위에서 다음은 **G5-01/G5-02의 시험 캠페인 선택·별도 공개 OBS 배너·중지**다. 실제 지급 계산을 도입하거나 HP 규칙을 임의 확정하지 않는다. G3-03 깨끗한 영상 경로는 미완료로 유지한다. 새 서버/기기등록/수동 표시키/옛 ZIP이나 게임 PC OBS 요구를 만들지 않는다. routine은 관련 범위, qualification은 배포 후보에서 수행한다.

미확정 입력: 비공개 치지직 앱/채널 승인, 대표 투컴 배선·기기, HP 단위·귀속·표시/보상 조건, 인프라. 비밀키를 대화나 공개 저장소에 넣지 않는다. 입력 부재를 목표 변경이나 독립 구현 중단의 이유로 삼지 않는다.
