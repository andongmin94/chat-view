## 현재 위치와 완료 기준

`[x]`는 명시한 좁은 개발 범위와 실제 근거다. 실계정·물리 투컴·배포 완료와 다르며 체크 개수로 완성도 비율을 계산하지 않는다.

기존 native 관리 버튼 → 시스템 브라우저 → 치지직 신원 확인 → 채널 확인 → 원래 관리 페이지를 유지한다. 브라우저 복구는 native 승인·역할·캠페인·저장 grant를 새로 만들거나 교체하지 않는다. 브라우저 관리 계정과 앱 계정은 자동으로 같다고 보장하지 않으며, 브라우저 창은 HUD 캡처 보호 밖이다.

실제 Chromium의 정상 HTML 로그인 폼이 403으로 거절되는 것을 확인했다. HTML 폼 POST에서 `Origin: null`을 유발하는 `no-referrer`를 페이지에 일괄 적용했던 경로를 보완해, 폼 문서는 `same-origin` 참조 정책을 사용한다. 정확한 Origin/CSRF 검사는 그대로이며 null/누락/다른 Origin을 허용하는 우회는 없다. 콜백·JSON·리디렉션의 기본 no-referrer 정책은 유지한다.

콜백의 cross-site 이동 경로가 이어지는 정상 복귀는 회전된 동일 브라우저 쿠키에 묶인 정확한 다음 페이지의 top-level GET 한 번만 허용한다. 최대 30초이며 기존 요청 만료를 넘지 않는다. 다른 페이지·iframe/fetch·POST·query·기존 쿠키에는 적용하지 않는다. PC 역할 승인과 관리 채널 확인은 별도로 눌러야 하며 이 허용 자체가 권한은 아니다. 취소/새 요청/쿠키 교체 뒤에는 재사용할 수 없다.

**다음 흐름:** 이번 코드의 실제 Chromium·전체 계약 결과를 확인하고 발견한 실패부터 수정한다. 기존 로그인 복구·채널 확인·계정 전환·취소/뒤로가기와 화면 문구를 끝까지 검수한다. 실계정·실서비스 HTTPS·물리 영상·D4 Q4/Q5는 별도 미완료다.
