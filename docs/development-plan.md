## 현재 위치와 완료 기준

`[x]`는 명시한 좁은 개발 범위와 실제 근거다. 실계정·물리 투컴·배포 완료와 다르며 체크 개수로 완성도 비율을 계산하지 않는다.

기존 native 관리 버튼은 원래 서비스의 고정 `/account`를 시스템 브라우저로 연다. 이번 서버 변경으로 **브라우저 세션이 없거나 만료되면 기존 치지직 인증 → 관리할 채널 확인 → 원래 계정/캠페인/활동 화면**으로 돌아온다. 앱을 다시 로그인하거나 PC·역할 승인을 새로 만들지 않는다. 브라우저 인증 중 발급받은 제공자 토큰은 신원 확인에만 일시 사용하며 기존 암호화 grant에 덮어쓰거나 구독을 재시작하거나 전역 revoke하지 않는다. 실제 제공자 측 동작은 실계정 확인이 필요하다.

관리 페이지 상단에 현재 브라우저 채널과 계정 전환을 표시한다. 전환/취소는 이 브라우저의 쿠키·CSRF·진행 중 인증을 폐기한다. 앱 계정·PC 승인·캠페인 선택은 바뀌지 않는다. 치지직 쪽 계정은 사용자가 해당 사이트에서 바꾸고 돌아와 확인한다. native 계정과 자동 일치/SSO 또는 제공자 계정 선택 강제 파라미터를 발명하지 않는다.

콜백은 같은 브라우저·일회성 state·5분 요청 한도에 묶이며, 새 요청/취소/만료/권한 철회 뒤의 늦은 결과는 관리 권한을 복원하지 않는다. 신원 확인 후에도 명시적 채널 확인 전에는 관리 권한이 없다. 이동 대상은 고정된 세 페이지뿐이며 URL·폼으로 owner/return URL/토큰을 받지 않는다. 만료된 변경 요청은 재로그인 뒤 자동 재실행하지 않는다. 브라우저 세션 만료는 401 복구 안내, browser cookie 없는 native Authorization 시도는 403으로 구분한다. 브라우저 화면이 HUD 캡처 보호 밖임을 유지한다.

**다음 흐름:** **기존 관리 화면의 실제 브라우저 로그인 복구·채널 확인·계정 전환·취소/뒤로가기 검수**다. 실제 브라우저가 설정하는 쿠키·SameSite·Sec-Fetch 메타데이터·CSP와 제공자 왕복 redirect 체인을 포함한다. HTTP 도구가 헤더/쿠키를 직접 보내는 이번 검사만으로 그 경로를 검증했다고 세지 않는다. 기존 인증을 재사용하고 D4 Q4/Q5와 물리 영상도 미완료로 유지한다.
