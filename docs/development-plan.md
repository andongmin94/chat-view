### 구현

- 캠페인 페이지는 기존 관리 계정의 승인·현재 송출 역할 소켓 수와 공개 snapshot 판정을 재사용한다. **제공자 승인 필요 / 송출 승인 없음 / 캠페인 미선택 / 승인 있으나 열린 송출 연결 없음 / 연결됐으나 유효 보고 없음 / 서버 표시 조건 충족**에 맞는 다음 행동을 보여준다. 게임 역할이나 다른 계정의 접속/보고로 대체하지 않는다.
- 선택과 승인이 유지된 단절은 송출 PC의 기존 연결창에서 현재 승인으로 복귀하도록 안내한다. 접속만 복구되면 여전히 새 보고를 기다린다. 새 유효 보고를 받으면 재선택·URL 교체 없이 같은 공개 소스로 돌아온다. 단순 보고 만료에도 캠페인을 다시 선택하라고 했던 잘못된 안내를 제거했다.
- 중지·철회로 선택이 해제된 경우는 여전히 직접 선택해야 한다. 새 승인·보고·관리 화면 새로고침이 이를 되돌리지 않는다. 표시 조건이 충족돼도 실제 OBS 화면·송출·광고 시청 실적의 확인은 아니다. 보고가 없음을 PC 종료나 시청자0명으로 단정하지 않는다.
- 복귀 안내는 읽기 전용이다. 기존 계정 상태·소스 설정으로 이동할 뿐 로그인·출력 시작·장면 변경·광고 선택을 실행하지 않는다. 네이티브 HUD/WGC·공개 렌더러·DB·지급 규칙·의존성·워크플로는 변경하지 않는다.

## 다음 사용자 흐름

먼저 이번 변경의 관련 CI를 확인하고 실패한 경로를 고친다. 이후에는 **새 송출 PC 승인 요청이 기존 송출 승인과 충돌하는409 → 해당 계정의 기존 연결 확인 → 사용자가 해당 연결만 해제 → 원래 요청에서 새 승인 → 광고 직접 재선택**을 연결한다. 현재 승인 POST는 충돌을 일반 오류로 반환한다. 기존 역할·동의·CSRF·연결별 해제를 재사용하고 역할 자동 이전, 다른 채널 해제, 게임 채팅 중지, 광고 자동 재선택은 하지 않는다.
