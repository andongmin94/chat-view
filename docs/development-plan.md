### 구현·검증 경계

- 채팅 첫 DOM이 비어 있을 때 사용자가 **현재 승인으로 표시 다시 시도**를 누르면 원래 채팅의 DOM·서버 카운트를 즉시 초기화한다. 서버가 갱신 전에 해당 게임 PC의 정확한 연결 ID를 철회할 때 실제 WinHTTP 401/403을 받아 이전 승인 복귀를 거부하고 새 브라우저 승인 필요 상태를 유지한다. 영상 캡처 상태는 원래 WGC/검정 덮개 경로에서 독립적으로 유지한다.
- 새 **로그인 / 연결**을 사용자가 직접 누른 경우에만 `NativeChatConnection::connect()`가 기존 `approval_denied_` 가드로 DPAPI에 저장된 **다른 계정의 승인 대체를 차단**한다. 동일 게임 역할의 새로운 브라우저 요청을 별도로 생성하며 CHZZK 합성 provider·계정/역할 직접 동의를 받은 뒤 실제 서버는 **기존과 다른 connection ID와 session credential**로 새 승인을 발급한다. 새 로그인 전/승인 대기 동안 이전 DOM·소켓 수·첫 글자 ACK·복귀 권한은 지우며 기존 저장된 다른 owner의 승인은 읽거나 삭제하지 않는다.
- 첫 새 채팅 문서는 0-row ACK 후 별도 제공자 첫 글자 수신·기존 **자체 DOM 첫 텍스트** 확인으로만 완성한다. 송출 광고/시청 실적/OBS/WGC 네트워크·계정 로그인은 자동으로 갱신/전환하지 않는다. 영상 출력 **재생 중**에는 같은 출력/검정 HWND·게임 창·선택 epoch/식별 번호·새 WGC 픽셀을 채팅 승인 전/후에도 유지한다. **사용자가 중지한 검정 출력**은 새 채팅 승인이 나와도 검정 덮개와 소비된 수신 동의를 유지하며, 사용자가 **새 시험 패턴 → 새 수신 확인**을 명시적으로 거쳐야만 영상이 재시작된다. 채팅 로그아웃 후에도 별도 영상은 사용자 중지 전까지 그대로다.
- 이전 철회+채팅/영상 흐름에서 이미 실행되는 **네이티브 Win32/WebView2/WinHTTP/WGC·서비스 HTTP/SQLite/ws** fixture를 두 새 모드 `redraw-reapproved-live`, `redraw-reapproved-black`으로 확장한다. 서버 parent는 최초 승인 1건 → 명시적 redraw 갱신 거부 정확히 1건 → 재로그인 페이지 1건(총2건), 재승인 새 연결 ID/새 session, 새 DOM 0행→첫 글자 표시, 다른 owner 보존, 명시적 새 승인 로그아웃을 검사한다. 기존 47 CTest에 **2개 추가하여 총49**. 기존 CTest 60초 제한·RUN_SERIAL·네이티브/OBS 검사 판정값을 유지한다. 실제 유료·실방송·물리 장비를 입증하지 않는다.
- **기능 커밋 `35d80ab307ab548b458dce520dab1ee1a04967af`, Windows development #412/run `38832527847`, job `116754314169`: MSVC 빌드 통과, routine CTest **47/49 통과·213.17초**, 기존 **47/47 전부 통과**. 신규 `redraw-reapproved-live`는 **4.40초**, `redraw-reapproved-black`은 **3.52초**에 실패했다. 서버 철회 → 명시적 새 브라우저 요청 → 신규 동일 게임 역할 승인·새 빈 DOM 단계까지 진행된 뒤, 새 승인 UI 관리 버튼 갱신 시점 확인과 테스트 자체의 실패한 수신 확인 호출 후 영상 선택 epoch 비교에서 실패했다. 실패한 검사와 성공한 기존 검사를 혼동하지 않는다.
- **후속 테스트 수정:** 새 DOM은 서버 승인 후 첫 수신 빈 프레임 ACK를 처리하는 순간, 보호 연결창의 **관리 버튼 상태**가 한 owner tick 늦게 갱신될 수 있다. 기존 15초 `Flow::wait` 안에서 지속 세션 문구와 관리 버튼이 **둘 다 실제로 갱신됐는지** 검사한다(비교 자체는 유지). 검정 출력 테스트가 직접 `Video::accept()`로 무효 수신 확인을 시도하면 운영 `stop()`이 의도적으로 epoch를 증가시키므로, 이 명시적 조작 **이후**의 영상 epoch를 새 로그인 전 기준으로 잡고, 새 로그인 동안에는 소비되지 않은 수신 확인 상태/검정 덮개를 비파괴적으로 검사한다. 새 채팅 첫 텍스트가 표시된 **후**에는 별도로 무효 수신 확인 시작을 다시 시도해 거부를 반드시 확인한다. 영상 창/픽셀/연결 역할·기존 승인 철회·새 로그인 횟수·첫 텍스트·다른 owner·기존 시간 한도를 그대로 유지한다.
- **후속 수정 `2e28b99d6c73d70a8da50986be72b811bd51ece7`, Windows development #413/run `38833509555`/job `116757396240`: MSVC 빌드 성공, routine CTest **48/49·223.32초로 전체 실패**. 새 `chat-view-companion-chat-redraw-reapproved-live` **5.09초 통과**, `-black` **5.71초 통과**. 기존 `companion-chat-reapproval` 10.64초, `redraw` 7.39초, `redraw-revoked-live/black` 3.93/3.87초, `native-chat-switch` 18.71초 통과. 정확히 하나의 이전 게임 PC 연결을 철회하고, 사용자가 새 브라우저 역할 동의를 직접 완료해 **다른 ID의 새 게임 승인·새 첫 글자**를 수신했다. 게임 출력 중에는 기존 WGC 출력/픽셀과 검정 HWND 유지, 검정 상태에서는 새 채팅만으로 게임 재시작 불가·새 패턴/새 수신 확인 후에만 재개, 새 승인 로그아웃 시 영상 유지 및 다른 creator 저장 승인 보존을 검증했다. 서버/provider/물리 수신 조건은 합성이다.
