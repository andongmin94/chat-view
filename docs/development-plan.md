# ChatView 작업 목표 체크리스트

갱신: 2026-09-29 (Asia/Seoul). 이번 변경은 이 문서와 같은 커밋의 **companion 선택 창 캡처 → 별도 SDR 확장 출력** 첫 구현이다. 시작 기준은 `7b9d92879a6954e9f5ffb019f52f48621051c851`이다. 이전 G5 패치/ZIP을 다시 적용하지 않는다.
이 파일이 유일한 현재 작업 목록이다. 목표는 [PRODUCT.md](../PRODUCT.md), 운영은 [development-workflow.md](development-workflow.md), 책임 구분은 [architecture.md](architecture.md)를 따른다.

> 최종 제품: 한 화면에서 채팅을 읽고 개인 HUD는 시청자에게 노출하지 않으며, 게임 PC에 OBS가 없는 투컴을 지원하는 자체 플랫폼. 선택한 공개 광고의 시청시간 기반 실적을 HP와 광고 수익으로 연결한다.

## 체크 규칙과 현재 위치

`[x]`는 명시한 좁은 개발 구현 범위의 반영과 관련 검사 근거다. 전체 제품·실계정·실제 방송·배포 완료가 아니며 체크 개수로 완성도 퍼센트를 계산하지 않는다.

기존 companion의 **Ctrl+Alt+Shift+V → 외부 창/별도 출력 직접 선택 → 확인 → 영상 표시 → 중지 시 검은 화면 유지**를 추가했다. 공식 Windows 창 캡처와 GPU 출력만 사용하며 OBS·인코더·네트워크 영상·오디오 경로는 추가하지 않았다. HUD를 숨기거나 게임 PC에서 OBS를 실행해 조건을 우회하지 않는다. 물리 캡처카드와 수신 PC의 녹화는 미검증이다.

**다음 사용자 흐름: G3-03의 실제 확장 출력·수신 영상 검증과 실패 시 검은 화면 유지.** 먼저 이번 Windows 컴파일/실제 WGC 픽셀/companion routine 결과를 확인하고 실패가 있으면 해당 코드부터 수정한다. 원격 검사와 물리 투컴 검증은 구분한다. 현재 실험 경로를 다시 만들지 않고 대표 배선·창 모드·잠금/복귀·출력 해제/장치 상실을 이어 검증한다. HP·단가·지급 규칙은 임의 확정하지 않는다.

## G3. 게임 PC에 OBS 없는 투컴

게임 PC에는 게임/챗뷰만, 송출 PC에는 OBS/플러그인이 있으며 개인 HUD가 송출 영상에 섞이지 않아야 한다.

- [x] **G3-01 — 동일 HUD의 OBS 비종속 실행.** 명시적 companion·로그인·중복 방지·종료를 유지한다.
- [ ] **G3-02 — 같은 계정의 채팅·방송 세션 연결.** [부분 구현] 역할 동의·공유·저장 복원·로그아웃과 최근 송출/녹화 활성 상태 전달이 있다. 독립 보고 작업·단기 권한·만료/철회를 처리한다. 활동 기록은 선택한 시험 캠페인 한정이며 일반 방송 전체 이력이 아니다. 장면/소스·다른 출력·실제 두 PC 확인은 남았다. 보고는 시청자 수신/캡처 제외 증명이 아니다.
- [ ] **G3-03 — OBS 없이 개인 HUD가 빠진 영상 전달.** [첫 실험 구현·Windows/하드웨어 검증 필요] `WindowCapture`의 공식 WGC 창 캡처 → D3D11/D2D 출력과 기존 companion의 직접 선택/확인/중지 UI를 추가했다. 복제·주 출력·HUD/게임/설정창 겹침·HDR·자체 창은 거절한다. 창 종료/최소화·보호/화면 변경은 중지하고 검은 출력창을 유지한다. SDR·영상만·최대 4096, 오디오/인코더/네트워크 전송은 없다. 일반 바탕화면 출력창이므로 다른 창/OS 오버레이·앱 종료 뒤 바탕화면까지 물리적으로 차단한다고 보장하지 않는다. 실제 캡처카드 녹화·게임 모드·지연/자원·잠금/복귀/장치 상실 검증이 남았다. [기술 계약](window-video-output.md).
- [ ] **G3-04 — 투컴 설치·실사용·영상 확인.** [하드웨어 필요] 지연·자원·재연결과 HUD 없는 녹화를 함께 확인한다.

## G5. 광고 선택 → 시청 실적 → HP → 수익

개인 HUD·출력 활성 보고·채널 전체 시청자 추정은 검증된 광고 시청 실적이 아니다. 시험 수치를 지급 가능한 실적으로 세지 않는다.

- [x] **G5-01 — 캠페인 목록·선택·중지의 첫 시험 흐름.** 기존 계정/CSRF의 시험 캠페인 한 개, 송출 승인 결합·철회·재시작 보존·재승인 후 재선택이 있다. 유료 운영/지급 완료가 아니다.
- [x] **G5-02 — 시험 캠페인의 별도 OBS 공개 소스 흐름.** `f083dc7`의 OBS 32.2.2/CEF 검사에서 13개 합성 PNG로 배치·숨김·중지·재선택·장면 복귀/장애·studio preview·페이지 유지/종료를 확인했다. 사용자 URL 배치 방식이며 원클릭 삽입은 없다. 실제 사용자 방송/녹화 파일·실계정·모든 환경·개인 HUD 제외 보장은 아니다.
- [ ] **G5-03 — 시청시간 관련 실적 집계.** [부분 구현] 비지급 출력 활동·누락 기록, 공식 Live API 표본, 마지막 표본 유지 추정과 측정 범위가 있다. 명시적 0명은 0, 누락/오류/만료/조회 한도 밖은 미측정이다. 녹화만/미리보기는 시청자 시간으로 계산하지 않는다. 계정 소유자만 조회하며 공개 페이지 조회로 증가하지 않는다. 수집은 기본 비활성이고 운영자의 실제 앱 권한·할당량·이용/보관 조건 확인 후 `CHATVIEW_AUDIENCE_SAMPLING=1`로 켠다. 실계정과 광고 노출/주의 계측은 미검증이다.
- [ ] **G5-04 — 서버 계산 HP·수익 내역.** [미구현·규격 미정] 비지급 시험과 예상/확정을 구분한다. 임의의 HP 0 지급 규칙은 없다.
- [ ] **G5-05 — 유료 운영·정산.** [미구현·규칙 필요] 단가·예산·배분·지급, 중복/초과 방지, 부정 실적·개인정보·광고 고지를 갖춘다.

## 이번 근거와 한계

- **시작 검사:** OBS HEAD `7b9d928`와 직전 구현 `7d422d5`의 완료 검사들을 조회했다. CHZZK #42 / `36528229056`, OBS 공개 소스 #5 / `36528229077` 성공이며 Windows #334 / `36528229003`의 x64는 scope skip이다. 새 캡처 코드의 빌드 근거로 대신하지 않는다. 직전 실제 native routine `8d4181e` / `36524659704` 성공도 이전 이력이다.
- **이번 코드:** `window-capture` 엔진, `video-layout`, `video-output-panel`, 기존 main/HUD 접근 경계와 작은 CMake 연결이다. 서버/로그인/광고/시청자 수집·의존성 버전·lockfile·기존 시험 한도·기존 캡처 보호 정책은 바꾸지 않았다. OS 기본 WGC/D3D11/D2D/DXGI 라이브러리를 사용한다.
- **직접 실행:** Linux g++ C++20 `-Wall -Wextra -Werror`로 `tests/video-layout-test.cpp` 컴파일/실행, **60 assertions 통과**. 크기/비율/정수 범위/출력 분리 검사이며 WGC·Windows·실제 픽셀 실행은 아니다.
- **추가한 Windows 검사:** 별도 프로세스의 합성 창과 실제 WGC/GPU 출력 위에서 HUD 모양 창을 캡처 제외 없이 겹친다. 출력 픽셀에서 게임 창만 보이고 로컬 겹침 창은 계속 보이는지, 크기 변경/letterbox/최소화/재시작/중지/종료를 확인한다. 실제 companion 실행 검사에도 새 창·출력 선택 UI, 미선택 거절, HUD 유지와 OBS 모듈 없음 검사를 추가했다. 아직 이 변경의 Windows 빌드/routine 성공은 확인하지 않았다.
- **현재 제한:** 첫 경로는 SDR 영상만이다. 2초 새 프레임 없음/오래된 프레임은 검게 처리하므로 정적인 창이 일시적으로 검게 될 수 있다. Stop은 비동기 신호, 최종 종료는 GPU 정리를 기다린다. 전체 화면/다른 창 대체 캡처는 없고 장치/창 복구 뒤 자동 시작하지 않는다. 실제 GPU/게임별 지원·캡처카드·물리 화면 두 개·수신 PC 인코딩 녹화·오디오·장시간 자원/지연은 미검증이다.
- **실행 환경:** 로컬에는 Windows 런타임/SDK가 없으며 저장소 전체 clone도 네트워크 이름 해석 실패로 확보하지 못했다. GitHub에서 지정 커밋의 원본을 읽어 변경 객체를 만들었다. 원격 ref 갱신 전까지는 반영 완료로 세지 않는다. qualification/배포 패키지·실계정 검사는 이번 범위가 아니다.
