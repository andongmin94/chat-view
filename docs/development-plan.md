### 구현

- 서버가 기존 승인을 거부한 뒤 **로그인 / 연결**은 새 브라우저 승인을 요청한다. 연결 유지가 켜져 있고 같은 서비스의 다른 계정이 저장돼 있어도 그 승인을 읽어 재사용하지 않는다. 연결 유지 선택은 새 동의에만 적용하고 평상시 저장 연결/현재 승인 복귀는 유지한다.
- 요청 시작 때 `approval_denied_`를 지우지 않는다. 기존 DisplayClient가 역할·membership을 검증하고 새 Receiving을 전달할 때만 지운다. 취소·브라우저 실패·잘못된 주소는 거부 상태를 유지한다. 새 승인 대기, 새 서버 소켓 수, 첫 텍스트 ACK를 구분한다.
- 재승인 대기 중 시스템 보호로 중단돼도 다른 저장 계정 자동 연결을 예약하지 않는다. 명시적 연결도 HUD 캡처 위험과 실제 제외 속성을 확인한다. 인증/갱신은 기존 클라이언트/서버가 책임진다. 새 의존성·기기등록·프로토콜은 없다.
- 채팅 로그인/취소/복귀/로그아웃은 WGC·출력창·검정 덮개·영상 동의를 조작하지 않는다. 새 채팅이 돌아와도 중지한 영상은 검정으로 남고 새 시험 패턴/수신 확인이 필요하다.

### 실패 검토 중 확인한 별도 취소 경계

`KillTimer`는 이미 큐에 놓인 `WM_TIMER`를 제거하지 않는다([Microsoft 계약](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-killtimer)). 기존 취소 함수는 재시도 수를0으로 지우지만 HUD 타이머 분기는 이를 읽지 않아 새 채팅 문서 위에 setup 페이지를 다시 로드할 수 있었다. 기존 시도 수0을 확인해 취소 메시지를 무시한다. 정상 재시도·오류 종료·시간 한도는 그대로다.

다음 제품 흐름은 G5-02의 **gaming-only 계정 → 송출 역할 준비 안내 → 시험 캠페인 선택 → 기존 공개 소스 사용**이다. `pages.mts`/`campaign-setup.js`의 URL 복사·실패/수동 복사·OBS 안내는 재구현하지 않는다. 현재 GET은 제공자 승인만으로 선택 버튼을 보이고 송출 역할 부재는 POST409에서 안내한다. 선택 전부터 역할 유무를 구분하며 철회 뒤 새 송출 승인만으로 광고를 자동 재선택하지 않는다. 공개 URL은 계정별 유지이므로 불필요한 교체를 요구하지 않는다.

물리 수신 HUD 제외 전 G3 완료 금지. 실계정·장시간/배포·유료 노출·HP/보상 규격·인프라는 미완료다. 비밀은 대화/공개 저장소에 넣지 않는다. main·새 장기 브랜치·검증 태그·강제 push·옛 ZIP·게임 PC OBS·자동 장면 변경·렌더 ACK의 수익 환산은 사용하지 않는다.
