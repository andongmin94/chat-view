## 현재 위치와 체크 규칙

`[x]`는 명시한 좁은 개발 범위와 검사 근거다. 전체 제품·실계정·물리 투컴·배포 완료가 아니며 체크 개수로 완성도 비율을 계산하지 않는다.

기존 설정창의 방송 전체 준비/안전 문구를 제거했다. **LOCAL HUD READY / HUD NOT READY**는 기존 로컬 상태 판정과 복구 동작만 설명한다. **OBS capture check**는 조회 불가·위험 보고·장면 조회 범위 내 위험 플래그 없음으로 구분하며, 위험 플래그가 없다는 이유로 초록색 안전 보장을 표시하지 않는다. **Audience video: NOT VERIFIED**는 상태와 독립적으로 유지한다. companion/OBS 관리 실행의 자체 연결창에도 로그인·채팅 표시·철회와 무관한 **수신 영상의 HUD 제외: 미검증** 안내를 추가했다. 기존 캡처 보호·로그인·자동 갱신·영상 출력·광고·HP 권한은 바꾸지 않았다.

직전 프레임 시각 보호 `4f1f048`의 **Windows #341은 빌드와 routine 성공**을 확인했다. D6 첫 픽셀 간헐 실패의 원인이 밝혀진 것은 아니다. 이번 D3 표시 변경은 해당 커밋의 Windows 검사를 별도로 확인한다. 다음 사용자 흐름은 **기존 설정창에서 자체 채팅 연결로 진입하고 외부 페이지 URL 설정과 책임을 구분하는 흐름**이다. 새 로그인 제품이나 기기등록을 만들지 않는다.

## 이번 근거와 한계

- **시작 확인:** 지정 다섯 문서와 OBS `9894c48`을 확인했다. **`4f1f048`/Windows #341/37114503379/job 111178575359**는 locked 의존성 설치·OBS 개발 라이브러리·ChatView 빌드/routine이 성공했다. qualification·설치/패키지 업로드는 실행하지 않았다. D6 원인 해결 근거가 아니며 이번 D3 변경의 검사로 대신하지 않는다.
- **제품 변경:** 기존 `src/config/main.cpp`와 `src/hud/native-chat-connection.cpp`의 표시만 수정했다. 설정창의 성공/문제 헤더를 로컬 HUD 범위로 한정하고, 불완전한 장면 조회가 안전 표시로 이어지지 않게 했다. 독립된 수신 영상 경고는 상태/복구 버튼과 분리된다. native 안내 공간은 기존 창 높이를 30 DIP 늘려 확보했다. 새로운 계정/기기/표시키/네트워크 호출/영상 권한은 없다. 내부 readiness 판정·복구 매핑, 서버, WGC, 의존성 버전, lockfile, 기존 테스트 시간/자원 한도는 변경하지 않았다.
- **실행 회귀 추가:** 실제 config 실행 파일에 합성 IPC/건강 보고를 전달해 초기 설정·정상·위험(표시/숨김)·장면 누락·로딩·재연결·송출/녹화 활성·잘못된 상태·복귀 시 고정 경고와 기존 복구 동작을 검사한다. 기존 companion 실제 실행에서 미로그인/잘못된 주소/중지 상태 경고와 창 내부 배치를 검사한다. 실제 WinHTTP→HUD/WebView2의 로그인 전/메시지 표시/철회 후 경고와 실제 글꼴에 따른 텍스트 높이도 검사한다. 합성 상태/채팅이지 실계정/수신 영상 검증은 아니다.
