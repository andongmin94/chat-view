## 이번 사용자 흐름: 승인 거부 후 새 로그인·첫 채팅 복귀

시작 HEAD는 `8901e6da2901321b5b408c8b6ca552ab23fc686e`. 최신 OBS를 확인하고 AGENTS → PRODUCT → development-workflow → architecture → 이 문서를 순서대로 읽었다. 직전 구현 `b6f49fc53939f6538bafb31b97c1763298bae464`의 **Windows #391/run `38056049101`/job `114224726040` completed/success**를 재확인했다. 이전 **43/43·162.01초**, revocation7.70초는 이전 구현 근거이며 이번 변경의 통과가 아니다.

### 변경한 동작

- 서버가 기존 승인을 거부한 뒤에는 기존 **로그인 / 연결**이 새 브라우저 승인을 요청한다. 연결 유지가 켜져 있고 같은 서비스의 다른 계정이 저장돼 있어도 그 저장 승인을 읽어 재사용하지 않는다. 연결 유지 선택은 브라우저에서 새로 동의한 승인에만 적용된다. 평상시 저장 연결·동일 현재 승인 복귀 경로는 유지한다.
- **요청 시작은 승인 완료가 아니다.** 기존 `approval_denied_`를 요청 시작 때 지우던 경로를 없애고, 기존 DisplayClient가 역할·membership을 검증한 새 Receiving을 전달할 때만 지운다. 취소·브라우저 실패·잘못된 주소·재시도는 거부 상태를 유지한다. 승인 대기에는 별도 대기 문구를 표시하며 접속 수와 첫 텍스트 확인은 새 응답 전까지 없다.
- 재승인 대기 중 Windows 보호로 중단되면 다른 저장 계정으로 자동 연결을 예약하지 않는다. 명시적 연결도 기존 HUD 캡처 위험/실제 제외 속성을 확인한다. 인증·갱신·철회 권한은 기존 DisplayClient/서버가 계속 책임지며 새 인증 체계·상태 프로토콜·의존성을 추가하지 않는다.
- 로그인·취소·재승인·채팅 복귀는 WGC/출력 HWND/검정 덮개/영상 수신 동의를 조작하지 않는다. 새 채팅이 돌아와도 중지한 영상은 검정으로 남고, 새 시험 패턴/수신 확인 뒤에만 영상이 재개된다.

### 이번 검사와 판정 경계

- **로컬 실제 실행:** 원격 blob SHA와 일치하는 원본 cpp에서 실제 begin/connect/clear_display/end 및 관련 분기·안내 함수 본문을 추출했다. 같은 대역 검사가 수정 전 `begin cannot discard the denial fence before approval`로 실패하고, 수정 후 **GCC336/336 및 Clang ASan+UBSan336/336 통과**했다. 저장 유무/주소·역할·연결 유지·중복 클릭·취소 후 재시도·새 수신·보호 중단을 검사했다. 이는 Win32/네트워크를 대역으로 둔 경계 검사이지 Windows 통합 실행은 아니다. Node22 `.mts` 문법 검사도 통과했다.
- 기존 `return`/`revoked` 모드의 검사와 제한을 유지하고, 동일 native 실행 파일/driver에 `reapproved` 모드를 추가했다. 새 CTest는 `chat-view-companion-chat-reapproval`이며 **기존43개 + 새1개**다. 새 검사도 CTest60초/driver45초, 기존 첫 표시15초·WGC첫프레임10초·중지2초·9픽셀/RGB오차8을 사용한다. 제한·판정 완화는 없다.
- 새 모드는 기존 서버 철회/영상 재시작까지 연결한 뒤, **연결 유지를 체크한 새 로그인 두 번을 승인 없이 각각 취소**한다. 첫 요청은 영상 출력 중, 두 번째는 명시적 검정 중지 상태다. 두 번 모두 다른 저장 계정은 그대로 남고, 거부 이유·소켓 미확인·복귀 차단과 영상 독립성이 유지돼야 한다.
- 마지막에는 연결 유지를 끈 새 브라우저 동의를 완료한다. 기존과 다른 connection ID, 같은 gaming 역할, 새 빈 구독과 새 첫 텍스트 DOM/ACK, 새 서버 접속 수를 요구한다. 새 승인으로 명시적 중지/복귀 뒤 새 영상 수신 확인·재시작·로그아웃까지 연결한다. 서버는 **로그인4회(초기1+취소2+새 승인1), 갱신5회(이전 복귀3+철회 거부1+새 승인 복귀1), 거부1회, 새 승인 로그아웃1회**를 요구하며 이전 승인·다른 계정 사용은 실패다. HTTP 자격증명 비교 실패도 실제 값을 출력하지 않는다.
- 제공자·출력 사각형·물리 수신 동의는 합성이다. 실제 HUD/WebView2·WinHTTP·HTTP/SQLite/WebSocket·WGC의 실행 결과는 아래 원격 상태로만 판정한다. 생산용 topology 우회·게임 PC OBS·실계정·유료 광고·배포 검증 주장은 없다.

## 다음 사용자 흐름

이번 재승인 Windows 결과를 확인하고 실패하면 해당 경로부터 수정한다. 통과 후에는 G5-02의 **기존 계정·시험 광고 관리에서 공개 소스 URL을 복사하고 OBS 브라우저 소스에 배치하는 동선**을 이어간다. 현재 관리 UI와 공개 소스 코드를 먼저 확인하고, 개인 채팅/관리 URL·자격증명과 혼동하지 않는 복사 결과·실패 안내·명시적 OBS 설정 안내를 완결한다. 자동 장면 변경이나 복사/렌더 ACK를 시청·수익 근거로 취급하지 않는다.

물리 수신 영상에서 HUD 제외를 확인하기 전에는 G3 지원 완료라고 표시하지 않는다. D1/D2/D4/D6/D7·실계정·장시간 자원/배포 qualification·G5 실제 노출/HP/보상 규격은 미완료다. 미확정 입력은 실제 앱/채널·수집 조건/할당량, 투컴 배선/기기, HP/보상 규격, 인프라다. 비밀은 대화/공개 저장소에 넣지 않는다. main·새 장기 브랜치·검증 태그·강제 push·옛 ZIP·게임 PC OBS는 사용하지 않는다.
