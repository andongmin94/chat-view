## 현재 흐름: 네이티브 로그인 대기 → 같은 승인 페이지 재열기 → 종료 후 새 로그인

시작 HEAD `5e2602a82605e53b2df8a536f8ee8fea3b432baa`에서 AGENTS → PRODUCT → development-workflow → architecture → 이 문서를 순서대로 읽고 직전 Windows #398/run `38075957417`/job `114282860153`의 최종 성공을 재확인했다. 직전 구현 `dc0da4691d0c6d44c361ee6a4b48885070114ae0`의44/44·184.06초, 플랫폼#68의312/312·Chromium16/16·OBS#20 합성13/13은 이번 실행으로 계산하지 않는다.

### 구현

- 기존 게임/송출 역할 연결창에 **브라우저 승인 페이지 다시 열기**와 현재 요청의6자리 확인 번호를 추가한다. `DisplayClient`가 한 번 전달한 검증된 원래 서비스 `/login/<id>`만 네이티브 메모리에 보관한다. 주소 입력칸·remember 선택·다른 저장 계정을 다시 읽지 않으며 새 challenge, 로그인 요청, 역할 이전, 영상 출력 또는 광고 선택을 만들지 않는다.
- WinHTTP 작업의 원래 요청 만료 시각을 공유하고 취소·로그아웃·실패·만료·승인 응답 수신 즉시 재열기 자격을 없앤다. URL을 이미 UI가 꺼냈거나 UI가 최종 메시지를 아직 처리하지 않았어도 시각/취소 상태를 확인한다. 완료 뒤에는 URL과 확인 번호를 지우며 일반 세션 복귀 권한과 혼동하지 않는다.
- 버튼은 보이는 보호된 연결창과 승인 대기 상태에서만 동작한다. 실제 HUD/패널 보호, 재진입, 종료 상태를 확인하고 시스템 브라우저 호출 중 동기 메시지가 요청을 바꾸면 이전 결과 안내를 덮어쓰지 않는다. 재열기 실패는 원래 요청을 유지하고 사용자가 재시도한다. 최초 브라우저 열기 실패의 기존 중지 동작은 변경하지 않는다.
- 종료·만료 뒤에는 기존 로그인 / 연결에서 명시적으로 새 요청을 시작하도록 안내한다. 브라우저 자체의 기존 수집 대기/충돌 복귀·같은 채널 재동의 경로를 그대로 사용한다. 브라우저는 HUD 캡처 보호 밖이다. proof/승인 토큰은 URL, 확인 번호, 로그 또는 렌더러로 전달하지 않는다.
- 새 엔드포인트·서버 프로토콜·DB·의존성·WGC·공개 광고·회계·CI 한도 변경은 없다. UI 행을 늘린 만큼 창/하단 안내 위치를 조정하고 기존 보호·영상 미검증 안내를 보존한다.

### 검사와 원격 상태

- 로컬에서 변경 전6개 코드/검사 파일의 바이트가 원격 blob SHA와 일치함을 확인했다. 변경 MTS의 Node22.16.0 문법 검사와 공백/diff 검사를 수행했다.
- 실제 변경 메서드를 추출한 경계 검사 **GCC21/21, Clang ASan/UBSan21/21**은 one-shot URL/원래 deadline·수집/취소/만료·재진입/예외·보호/숨김 거부를 확인했다. Win32·작업 상태를 대역으로 둔 로컬 검사이며 네이티브 실행이나 WinHTTP 검증을 대신하지 않는다.
- 기존 `native-display-client`의14개 시나리오와 모든 판정/시간 제한을 유지하고 게임 역할·로그인 중지·짧은 응답 수명 만료·브라우저 거부4개를 추가했다. 기존 송출 시나리오도 같은 재열기 검사를 수행한다. 실제 연결창 버튼, 보호 속성, 동일 URL/확인 번호, 편집값 무시, 브라우저 호출 실패와 명시적 재시도, 최종 UI 갱신 전 재열기 거부, 새 요청→WinHTTP→자체 DOM 첫 텍스트→철회를 검사한다.
- 네이티브 검사의 브라우저 실행은 기존 callback seam이며 서버는 실제 DisplaySessionGateway/SQLite/ws, 승인과 제공자는 합성이다. 만료 검사는 최초 응답의 수명만2초로 줄여 실제 클라이언트 deadline을 검사하며 생산5분 제한을 늘리지 않는다. 실제 시스템 브라우저·치지직 계정·물리 투컴·유료 노출 검증이 아니다.
- **이번 코드의 원격 빌드·CTest는 아직 미확정이다.** OBS에 코드/회귀 검사/이 계획을 함께 반영한 뒤 해당 SHA의 실제 결과를 기록한다. 컨테이너의 GitHub DNS 실패로 전체 checkout/의존성 설치와 Windows 실행은 로컬에서 하지 못했다.

## 다음 사용자 흐름

이번 재열기 변경의 원격 결과를 먼저 확인한다. 이후 **로그인 대기 중 연결 중지 → 열려 있는 브라우저의 오래된 승인 요청 종료 확인 → 사용자가 새 로그인 시작**을 이어간다. 현재 중지는 로컬 poll만 종료하며 서버 요청은 만료까지 남는다. 원래 verifier로 해당 요청만 취소하는 경계를 기존 로그인 수명에 추가할지 실제 취소/수집 경쟁을 확인하고 구현한다. 다른 승인·게임 채팅·영상 출력·광고를 철회하거나 자동 재선택하지 않는다. 이미 수집한 승인과 아직 대기 중인 요청을 구분하며, 응답 유실을 취소 완료로 단정하지 않는다.
