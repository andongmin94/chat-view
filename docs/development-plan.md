# ChatView 작업 목표 체크리스트

갱신: 2026-10-04 (Asia/Seoul). 시작 기준 **`3a4a9655d8114da01dd6a53637e7f464fcbc8d37`**. 이번 변경은 **D4 캡처 qualification 모듈의 종료·취소·임시 장면 항목 정리**다. OBS에서만 이어가며 옛 ZIP/패치·다른 브랜치를 사용하지 않는다.
목표는 [PRODUCT.md](../PRODUCT.md), 운영은 [development-workflow.md](development-workflow.md), 책임은 [architecture.md](architecture.md)를 따른다. 이 문서가 유일한 현재 작업 목록이다.

## 현재 위치와 완료 기준

`[x]`는 명시한 좁은 개발 범위와 실제 근거다. 실계정·물리 투컴·배포 완료와 다르며 체크 개수로 완성도 비율을 계산하지 않는다.

직전 브라우저 복구·채널 확인·전환·취소/Back은 `24444b6`의 CHZZK #51에서 실제 Chromium 9개 및 Windows/Linux × Node22/24 전체 계약이 통과했다. 이번에는 인증·페이지·native 승인·캠페인·채팅 전달을 변경하지 않는다.

D4의 Q4/Q5 인수인계 표현을 실제 코드로 좁혔다. 현재 Control Center에는 그 이름의 캡처 시험 UI가 없다. 해당 종료 위험은 **CI 전용 `obs-capture-qualification-plugin.cpp`**에서 확인했다. worker가 동기 UI task 완료를 기다리고 UI의 unload가 worker를 join하는 순환 대기 가능성, `obs_scene_add`가 돌려준 빌린 item을 보유 참조 없이 나중에 쓰는 수명 위험이다. 실제 교착 재현/물리 방송 장애를 관측했다고 주장하지 않는다.

현재 장면의 소유 참조는 frontend 이벤트에서 한 번 얻어 worker에 이전한다. worker의 생성·배치·정리는 libobs core scene API와 명시적인 참조만 사용하고 frontend task를 기다리지 않는다. 시험 item은 scene lock 안에서 addref하며, 정상/실패/취소의 같은 정리 경로에서 해당 item 제거·item 참조 해제·showing 감소·source/scene 참조 해제를 수행한다. 외부에서 item이 이미 제거돼도 보유 참조로 정리하며 다시 표시하지 않는다. EXIT/장면/scene collection 전환은 취소한다. 종료 시 worker 완료를 기다리는 기존 구조는 유지하되 동기 UI 요청의 역방향 의존을 제거했다.

원래 사용자 항목과 설정을 스냅샷으로 덮어쓰지 않는다. 시험이 추가한 항목만 제거하므로 시험 중 사용자가 바꾼 위치도 보존한다. 시험 창은 소유 worker에서 정리한 후 결과를 기록한다. 이것은 CI 시험 상태 정리이며, 제품에 새 시험 UI·프로필 복원 기능을 추가하거나 실제 수신 영상의 HUD 제외를 검증한 것이 아니다.

**다음 흐름:** 이번 native 빌드/실제 libobs 회귀 결과를 먼저 확인한다. 그다음 **companion 영상 출력 중 캡처 대상 종료 → 검정 유지 → 새 대상·시험 패턴 재선택**을 기존 UI에서 확인한다. 실제 OBS frontend 종료/장면 전환과 캡처 qualification은 배포 후보의 별도 검증으로 유지하며, 이번 core 회귀만으로 종료 전체나 D4 전체를 닫지 않는다.

## 이번 근거와 한계

- **시작:** 지정 문서를 순서대로 읽고 OBS `3a4a965`를 확인했다. 이전 native/브라우저 결과는 Git history의 `3a4a965`와 `24444b6` 기록이며 이번 변경의 실행 결과로 대신하지 않는다.
- **API:** 실제 빌드 기준 OBS 32.2.2의 `libobs/obs.h` 및 공식 Scene API에서 borrowed `obs_scene_add`, 명시적 item ref, scene atomic update를 확인했다. 새로운 OBS/Windows 의존성이나 제품 설정을 추가하지 않는다.
- **작성한 검사:** 실제 libobs scene/source를 사용해 정상/idempotent 종료, 부분 생성 실패, 예외 unwinding, 외부 item 제거, 시험 중 사용자 편집, 생성 전/후·배치 후 worker 취소와 주 스레드 join을 검사한다. 가짜 libobs 구현이나 UI 큐 pumping으로 통과시키지 않는다. 실제 모듈과 같은 소유권 helper를 사용한다.
- **실행 상태:** 로컬에는 Windows/libobs 실행 환경이 없어 해당 native 검사를 실행하지 못했다. 빌드에 새 10초 제한 routine CTest를 추가했으며 원격 결과는 확인 후 기록한다. 전체 OBS frontend/Display Capture/실제 종료와 물리 영상·실계정·qualification은 이번 core 검사만으로 검증되지 않는다.
- **보존:** 기존 캡처 픽셀/색상 조건·각 단계 시간·재시도 예산·기존 CTests는 유지한다. CI 전용 새 test executable만 libobs에 연결하며 gaming-PC companion 및 window-capture library에는 OBS 의존성을 추가하지 않는다. 배포 패키지에 시험 모듈을 설치하지 않는다.
