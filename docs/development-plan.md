갱신: 2026-09-21 (Asia/Seoul). 현재 구현 기준: `ce73e6cabb44d61f0d229911eda9b4853f561a0e` (G4-05/G3-02 첫 서버 구현).
이 파일이 유일한 현재 작업 목록이다. 최상위 목표는 [PRODUCT.md](../PRODUCT.md), 구현·검증 운영은 [development-workflow.md](development-workflow.md), 책임 구분은 [architecture.md](architecture.md)를 따른다.

> 최종 제품: 스트리머가 한 화면에서 채팅을 읽고, 개인 HUD는 시청자에게 노출하지 않으며, 게임 PC에 OBS가 없는 투컴을 지원하는 챗뷰 자체 플랫폼. 스트리머가 선택한 공개 광고의 시청시간 기반 실적을 HP 진행과 광고 수익으로 연결한다.

## 체크 규칙과 현재 위치

`[x]`는 **해당 항목에 적힌 좁은 개발 구현 범위**가 OBS에 반영되고 관련 routine/contract 근거가 있다는 뜻이다. 전체 제품·실계정·실제 방송·배포 완료를 뜻하지 않는다. 실계정·투컴 하드웨어·유료 정산은 각 별도 항목이 체크되어야 한다. 체크 개수로 전체 완성도 퍼센트를 계산하지 않는다.

기존 **한 화면 HUD, OBS 연동 기반, OBS 없는 companion, CHZZK 자체 채팅 전달, 브라우저 로그인과 현재 실행 자동 갱신·선택적 재실행 연결 유지**에 더해, **계정별 채팅 경로를 분리하는 HTTPS 서버와 같은 계정의 게임/송출 역할 승인·저장·해제**를 구현했다. G4-05/G3-02는 부분 구현이며 운영 배포나 실제 두 PC 검증 완료가 아니다.

**다음 사용자 흐름: G4-05 + G3-02 연속성 — CHZZK 승인을 보호 저장하고 서버를 재시작해도 같은 계정의 두 PC가 재동의 없이 채팅 연결을 복원한다.** 기존 서버·로그인·세션을 확장한다. 별도 하드웨어 등록 제품을 만들지 않는다. G3-03 영상 경로와 G5 광고 흐름도 무기한 뒤로 미루지 않는다.

## G1. 한 스크린에서 게임·작업과 채팅을 함께 본다

완료 기준: 실제 지원 게임/창 모드에서 채팅이 읽히고 게임 조작을 방해하지 않는다. 기존 main의 핵심 사용 경험을 계승하되 Electron 코드를 유지할 의무는 없다.

- [x] **G1-01 — 투명 개인 HUD와 챗뷰 자체 텍스트 채팅 화면.** 네이티브 렌더링과 자체 메시지 표시 경로를 구현했다. 실제 치지직 채널 확인은 G4-06이다.
- [x] **G1-02 — 클릭 통과, 이동·크기 조절, 위치·DPI 저장, 단축키.** 기존 네이티브 구현과 Windows 검사가 있다.
- [ ] **G1-03 — 실제 게임에서의 가독성과 조작감 완성.** [실환경 미확인] 포커스/마우스/키보드를 빼앗지 않는지 확인하고 필요한 표시·조작 개선을 적용한다.

## G2. OBS 플러그인으로 연동하고 개인 HUD만 송출에서 제외한다

완료 기준: **스트리머에게는 HUD가 계속 보이고, 시청자 영상에는 개인 HUD가 없다.** HUD 자체를 숨겨 성공으로 처리하지 않는다. 공개 광고는 G5의 별도 출력이다.

- [x] **G2-01 — OBS 플러그인, 설정 진입, HUD 실행·종료 연동.** OBS/HUD 프로세스 분리와 기존 제어 경로를 구현했다.
- [ ] **G2-02 — 원컴에서 읽을 수 있는 HUD와 송출 제외를 동시에 달성.** [부분 구현] 캡처 제외 설정·보호 정책은 있지만 위험 시 HUD를 숨기는 현재 제한을 지원 영상 경로로 해결해야 한다.
- [ ] **G2-03 — 방송 시작·장면 전환·복귀와 지원 조건 안내.** [부분 구현·실환경 미확인] 지원 캡처 방식/창 모드에서 G2-02를 유지하고 확인한 상태와 미지원 상태를 정확히 표시한다. `READY TO STREAM`을 방송 전체 보장으로 사용하지 않는다.

## G3. 게임 PC에 OBS 없는 투컴 방송에서 사용한다

완료 기준: 게임 PC에는 게임과 챗뷰만, 송출 PC에는 OBS와 챗뷰 플러그인이 있으며, 게임 PC의 개인 HUD는 계속 보이고 송출 영상에는 섞이지 않는다.

- [x] **G3-01 — 동일 HUD의 OBS 비종속 개발 실행.** 명시적 `--companion`, 기존 로그인/연결창, 중복 실행 방지·종료를 구현했다. 로컬 OBS 부모 없이 실제 실행하는 routine 검사가 있다.
- [ ] **G3-02 — 두 PC를 같은 사용자의 채팅·방송 세션에 연결.** [부분 구현] 기존 브라우저 승인과 갱신 자격증명에 게임/송출 역할을 결합했다. 같은 계정은 논리 세션을 공유하고 송출 역할은 하나만 승인된다. SQLite 저장·갱신 시 역할 유지·계정별 연결 해제를 구현했다. 별도 기기 등록이나 하드웨어 ID는 없다. 네이티브 실행 역할 자동 연동·역할 상태 UI·실제 OBS 출력 상태/방송 생명주기 전달은 아직 남아 있다. 역할 조회는 캡처 상태를 `unverified`로 반환한다.
- [ ] **G3-03 — 게임 PC의 OBS 없이 개인 HUD가 빠진 영상 전달 경로.** [미구현·방식 미확정] 실제 가능한 캡처카드/출력 구성을 선정하고 구현한다. OBS 숨김 실행·프로젝터·다른 방송 프로그램 필수 설치로 조건을 우회하지 않는다.
- [ ] **G3-04 — 투컴 설치·실사용 연결과 실제 영상 확인.** [하드웨어 확인 필요] 설치/실행, 채팅, 재연결, 종료, 지연·자원 사용과 HUD 없는 녹화 결과를 함께 확인한다.

## G4. 치지직부터 챗뷰 자체 채팅 플랫폼을 만든다

완료 기준: 사용자는 개발자 비밀키나 수동 표시 키가 아니라 로그인·연결 동의로 자기 채팅을 보고, 방송 중 유지하며, 재실행 후 이어 쓰고 로그아웃할 수 있다. 외부 채팅 웹페이지를 보여주는 것에서 끝나지 않는다.

- [x] **G4-01 — 치지직 공식 인증·채널 조회·채팅 구독 모듈.** 코드와 합성 제공자/실제 Socket.IO 라이브러리 검사가 있다. 실계정 성공은 G4-06이다.
- [x] **G4-02 — 서버에서 챗뷰 자체 네이티브 화면까지 메시지 전달.** 로컬 HTTP/WebSocket → WinHTTP → HUD/WebView2 경로를 합성 메시지로 확인했다. D1의 과거 간헐 실패는 신뢰성/배포 추적 항목으로 남긴다.
- [x] **G4-03 — 로그인 버튼 → 시스템 브라우저 동의 → 앱 복귀 → 내 채팅 표시.** 요청별 verifier/challenge, 브라우저 확인 번호·채널 동의, 승인 결과의 소유자/승인세대 결합, 네이티브 결과 수신과 자체 화면 표시를 구현했다. 수동 표시 키 복사는 정상 UX에서 제거했다. CHZZK #29와 Windows routine #321이 통과했다. 실계정 확인은 G4-06이다.
- [x] **G4-04 — 현재 실행 자동 갱신, 선택적 ‘이 PC에서 연결 유지’, 재연결, 로그아웃.** 모든 승인 연결은 실행 중 `chat:renew`로 자동 갱신된다. ‘연결 유지’는 재실행용 Windows DPAPI 저장만 결정한다. 갱신 자격증명은 해시로만 SQLite에 저장하며 채팅/제공자 자격 증명을 저장하지 않는다. 재실행 자동 연결, bounded 재연결, 철회 시 저장 제거와 로그아웃을 구현하고 Windows routine #321이 통과했다. 별도 기기 등록 UI/하드웨어 ID는 없다.
- [ ] **G4-05 — 여러 스트리머가 사용하는 운영 서비스.** [부분 구현] `platform/server/main.mts`의 직접 TLS 실행, 서버측 `/users/me` 기반 계정 식별, 계정별 단일 채팅 upstream/표시 경로, 개별 브라우저 인증·CSRF, 서버측 단일 실행 갱신과 bounded 재연결, 계정/연결별 철회를 구현했다. 개발용 loopback 도구를 공개 서버로 바꾸지 않았다. CHZZK 승인은 아직 메모리 보관이라 서비스 재시작 후 재동의가 필요하다. 제공자 승인 보호 저장·운영용 접근/용량 제한·실제 인증서/호스팅·잠금 의존성 전체 검사·Windows 실제 서비스 연결은 남아 있다.
- [ ] **G4-06 — 실제 치지직 계정으로 전체 사용 확인.** [비공개 앱/채널 승인 필요] 동의 → 실제 메시지 표시 → 장시간 유지/재연결 → 로그아웃/권한 철회를 확인한다.

## G5. 광고 선택 → 시청 실적 → HP → 광고 수익을 연결한다

완료 기준: 스트리머가 선택한 광고가 시청자에게 노출되고, 허용된 시청시간 관련 근거에 따라 HP와 수익 기록이 변한다. 개인 HUD 트래픽이나 시험용 수치를 지급 가능한 실적으로 세지 않는다.

- [ ] **G5-01 — 광고 배너/캠페인 목록·선택·중지.** [미구현] 우선 한 광고가 끝까지 동작하면 된다. 초기 캠페인은 운영자가 등록해도 된다.
- [ ] **G5-02 — 선택 광고의 별도 OBS 공개 출력.** [미구현] 스트리머가 확인한 위치/크기로 표시하고 변경·중지할 수 있게 한다. 개인 채팅 HUD와 분리한다.
- [ ] **G5-03 — 시청시간 관련 실적 수집·집계.** [미구현·계측/사용 권한 확인 필요] 방송 시간, 추정 시청자 시간, 실측 광고 시청시간을 구분하고 누락·중복·중단을 처리한다.
- [ ] **G5-04 — 서버 계산 HP와 수익 내역 표시.** [미구현·세부 규격 미정] 우선 비지급 시험 흐름을 완성하고 예상·확정 수익을 구분한다. HP 0에서만 지급한다는 조건을 임의로 만들지 않는다.
- [ ] **G5-05 — 실제 유료 운영·정산.** [미구현·운영 규칙 결정 필요] 단가·예산·배분·지급 조건, 중복/예산 초과 방지, 부정 실적 검토, 개인정보·광고 고지·지급 기록을 갖춘다.
